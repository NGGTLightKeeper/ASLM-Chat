## New Features

- **[Web Search]**: Added an optional, zero-install Tor/onion access layer. This feature does not bundle or install Tor; it dynamically discovers an existing system daemon or Tor Browser binary to spawn its own process, or reuses a running SOCKS proxy.
- **[Web Search]**: Implemented a deep onion search pipeline that searches via provider onions, runs parallel scraping, and compresses content via BM25.
- **[Web Search]**: Added anchored auto-expansion capability (`harvester`) to discover legitimate `.onion` URLs via `Onion-Location` headers from trusted clearnet anchors, persisting entries to `_cache/onion_registry.db`.
- **[Web Search]**: Extended `read_page` to seamlessly fetch `.onion` links over Tor when enabled, using a dedicated timeout profile.
- **[Web Search]**: Pre-warming support for Tor to prevent cold-start latency when making the first onion fetch.
- **[Documentation]**: Added comprehensive documentation for the new `core/fetch/onion` package, including its modules (`harvester`, `models`, `registry`, `resolver`, `search`, `store`, `tor_proxy`, `transport`) and associated test suites.

## API Changes

- **[mcp-server]**: The search query schema now includes an `onion` opt-in boolean parameter. This capability is dynamically advertised and honored only when the `tor.enabled` configuration is set to true.
